# 관리자(연구책임자) 가이드

## 1. 설치·배포

README 의 [빠른 시작](../README.md#빠른-시작-연구책임자-약-10분) 참고. 요약: `npm install` → `npx wrangler login` → `npm run setup`.

- `setup` 은 D1 생성 → `wrangler.jsonc` 에 `database_id` 기록 → 마이그레이션 → 배포 → 관리자 토큰 발급을 순서대로 수행합니다. 각 단계는 재실행해도 안전합니다.
- 관리자 토큰을 잃어버렸으면 `npm run bootstrap -- --name "이름" --id juho` 처럼 실행해 관리자 사용자를 재보장하고 새 토큰을 발급합니다 (`--id` 는 영문·숫자·하이픈만, 생략 시 `admin`).
- 비상용: `npx wrangler secret put ADMIN_TOKEN` 으로 넣은 값은 항상 관리자로 인증됩니다 (예약 사용자 `bootstrap-admin`, 관리자 화면에서 비활성화하면 차단). 운영 안정화 후 `npx wrangler secret delete ADMIN_TOKEN` 권장.

## 2. 조직 구성

1. **카테고리(팀)** = 연구 그룹. 같은 팀 구성원끼리만 서로의 프로젝트가 보입니다. 주제별(예: "LLM 응용", "시계열")이나 과제별로 만드세요. 한 연구원이 여러 팀에 속할 수 있습니다.
   - **트랙**: 논문(기획→…→검토·투고) 또는 캡스톤(주제·문제 발견→시장·사업모델→MVP 빌드·배포→피드백·개선→사업성·최종보고→최종 발표). 프로젝트가 생긴 뒤에는 트랙을 바꿀 수 없습니다.
   - **캡스톤 수업 운영 예**: 학기마다 "캡스톤 2026-2" 팀(캡스톤 트랙, 즉시 가입)을 만들고, 조교·심사위원을 **평가자**로 배정합니다. 학생 팀은 프로젝트 하나를 만들고 팀원을 협업자로 추가합니다. 4주차·8주차·12주차 마일스톤에 평가자들이 루브릭으로 채점하고, 팀은 다음 보고서 전에 답변을 답니다. 팀 보고서를 뽑으면 루프별 기록과 평가·답변이 함께 나옵니다.
2. **가입 정책**(팀별): 승인 후 가입(기본, 리드·관리자가 로비 가입 요청을 승인) / 즉시 가입 / 초대만(관리자가 직접 배정).
3. **리드** = 팀 안에서 검토(승인/수정요청)·팀원 프로젝트 편집·가입 요청 승인 권한. 보통 지도교수·박사과정. 관리자는 모든 팀의 리드 권한을 가집니다.
4. **연구원 온보딩**
   - 자율 신청: 연구원이 `/#/apply` 에서 신청 → [관리자] → 발급 신청 에서 승인(이름·ID·소속·역할 조정 가능) → 연구원이 수령 코드로 토큰을 직접 1회 수령. 관리자는 토큰을 보지 않습니다.
   - 직접 등록: [관리자] → 연구원 에서 "등록과 동시에 토큰 발급" → "안내문 복사" 로 URL + 토큰 + Claude Code 명령을 전달.
   - AI 위임: 연구원이 AI 도구에 `/connect` 주소를 주면 AI 가 신청·수령·연동을 대신합니다. 관리자는 승인만 하면 됩니다.
5. 스팸이 걱정되면 `npx wrangler secret put SIGNUP_CODE` 로 신청 코드를 설정하고 연구원에게만 알려주세요. 공개 신청을 아예 끄려면 `SIGNUP_ENABLED="false"`.
6. **핀 열람 (공개 카테고리)**: 외부 심사위원이나 수업 참관자에게 가입 없이 보여주려면 [관리자] → 카테고리 → 수정에서 **공개 열람 허용**을 켜고 **핀**(영문·숫자 4~12자)을 정하세요. 그 뒤 `/#/view` 주소와 핀을 말로 전달하면 됩니다.
   - 핀은 바꿀 때까지 유지되고, 열람 세션은 24시간마다 핀을 다시 넣어야 합니다. 핀을 바꾸거나 공개를 끄면 지금 보고 있는 사람도 즉시 끊깁니다. 표의 "열람 세션 n" 옆 [만료] 로 핀을 유지한 채 세션만 끊을 수도 있습니다.
   - 열람자는 읽기만 가능하며(서버에서 강제) 구성원 이메일·가입 요청·초안 평가는 보지 못합니다. 5회 틀리면 10분 잠금.
   - 학기가 끝나면 공개를 끄거나 카테고리를 보관하세요. 둘 다 열람 세션을 정리합니다.

### 학생이 "토큰이 유효하지 않다"고 할 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 발급 신청 표에 **미수령**(빨강) | 수령 코드로 [토큰 받기]를 아직 안 눌렀거나 코드를 잃어버림. 로그인 창에 수령 코드(clm_)를 넣으면 "토큰이 아님" 안내가 뜸 | 학생에게 수령 링크에서 [토큰 받기]를 누르라고 안내. 코드를 잃어버렸으면 해당 행의 **[수령 코드 재발급]** → 새 링크를 전달 |
| 수령했는데 로그인 실패 | 오타(다른 기기에서 옮겨 적음), 앞뒤 잘림, 다른 서버 토큰 | 토큰은 rn_ + 40자. [연구원] 탭에서 토큰을 새로 발급해 안내문으로 전달하거나, 발급 신청 표의 [코드 재발급]으로 다시 수령하게 함 |
| 같은 학생이 두 번 신청 | 첫 신청의 코드를 잃어버리고 재신청 | 이제 같은 이메일로는 재신청·중복 승인이 막힙니다(409). 이미 생긴 중복 계정은 [연구원] 탭에서 비활성화 |
| "회수된 토큰" | 관리자가 회수함 | 새로 발급 |
| 토큰 분실·기기 교체 | — | 학생이 `/#/reissue` 에서 등록한 이름+이메일을 넣으면 **즉시 새 토큰 발급**(기본: 기존 토큰 회수). 관리자 손이 가지 않으며 활동 로그에 "본인 토큰 재발급"으로 남습니다. 이름·이메일을 아는 타인이 발급받을 수 있는 구조이므로, 승인 절차를 두고 싶으면 `wrangler.jsonc` 에 `REISSUE_AUTO: "false"` → 요청이 [발급 신청] 탭에 "재발급"으로 올라오고 승인 후 학생이 수령 |

## 3. 대시보드 읽는 법

- **단계 분포**: 진행 중 프로젝트가 어느 단계에 몰려 있는지. 실험 단계 정체가 길면 리소스 점검.
- **최근 6주 활동**: 일별 기록·코멘트·단계 갱신 수. 방학·학회 시즌 패턴 확인.
- **연구원별 현황**: 14일 이상 기록이 없으면 붉게 표시. 면담 대상.
- **검토 대기**: 오래된 순. 리드가 놓친 요청.
- **다가오는 마감**: 목표 학회 마감 기준.

## 3'. 공지

- **홈 [+ 공지 올리기]** 또는 **팀 페이지 [공지] 탭**에서 마크다운으로 작성합니다. 관리자는 전체 공지(모든 팀)와 팀 공지, 리드는 자기 팀 공지만.
- **상단 고정**을 켜면 목록 맨 위 + 팀 페이지 상단 띠에 제목이 표시됩니다. 발표 준비 안내처럼 학기 내내 봐야 하는 것은 고정하세요.
- 학생의 AI 도구도 `list_notices` 로 읽습니다. "슬라이드 5장 이내" 같은 요구사항을 문장으로 분명히 적으면 AI 가 발표 자료·기록을 만들 때 따릅니다. AI 로 올리려면 `post_notice`.
- **내리기**는 소프트 삭제입니다. [내린 공지 보기]에서 다시 올릴 수 있습니다. 게시·수정·내림은 팀 활동 피드에 남습니다.

## 4. 검토 워크플로

1. 연구원이 기록에 "검토 요청" → 팀 페이지 [검토 대기] 와 관리자 개요에 표시
2. 리드가 기록을 읽고 코멘트 → **승인** 또는 **수정 요청**(코멘트 필수)
3. 수정 요청된 기록은 붉은/노란 테두리로 표시. 연구원이 수정 후 다시 요청
4. 승인된 기록은 보고서에 "승인" 배지

AI 도구로도 가능: 리드가 Claude Code 에서 `/research-note:review llm` 을 실행하면 검토 대기 기록을 읽고 코멘트 초안을 만들어 확인 후 남깁니다.

## 5. 토큰 정책

- 토큰은 개인 비밀번호와 같습니다. 서버에는 해시만 저장되어 관리자도 다시 볼 수 없습니다.
- 한 사람이 여러 토큰(노트북용·서버용)을 가질 수 있습니다. 라벨로 구분하세요.
- 퇴소·유출 시 [토큰] 탭에서 **회수** → 즉시 차단. 계정 자체를 막으려면 연구원 수정에서 **비활성화**.
- 토큰이 노출된 채 Git 에 커밋되지 않도록 연구원에게 안내 (`.mcp.json` 을 커밋하지 말 것, 환경변수 사용).

## 6. 보고서·아카이브

- 팀 보고서(기간 지정)는 주간 미팅·과제 보고에 바로 쓸 수 있습니다. HTML 을 열어 "PDF 로 저장".
- 논문이 끝난 프로젝트는 상태를 **완료**로, 중단은 **보관**으로. 보관은 목록에서 숨기되 데이터는 유지됩니다.
- 학기 말 백업: `npx wrangler d1 export DB --remote --output 2026-1.sql`

## 7. 커스터마이즈·운영

- 기관명·마크: `wrangler.jsonc` `vars`
- 단계 라벨: `src/env.ts`
- 배포: 코드 수정 후 `npm run deploy`. 스키마 변경은 `migrations/` 추가 후 `npm run migrate:remote`
- 로그: Cloudflare 대시보드 → Workers → research-note → Logs (observability 활성화됨)
- 도메인 연결: Workers → Settings → Domains & Routes 에서 커스텀 도메인 추가 (MCP URL 도 함께 바뀜)
