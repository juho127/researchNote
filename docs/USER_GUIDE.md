# 연구원 가이드

## 시작

1. **토큰 받기** (둘 중 하나)
   - 접속 URL 의 **발급 신청** 에서 이름·이메일·희망 팀을 적어 신청 → 화면의 **수령 코드**를 보관 → 연구책임자가 승인하면 수령 링크에서 토큰을 **한 번만** 받습니다.
   - 또는 AI 도구(Claude Code 등)에 `https://<URL>/connect 를 읽고 연구노트를 연동해줘` 라고 말하면 AI 가 신청부터 연동까지 대신합니다.
2. 토큰(rn_…)으로 로그인. 토큰은 브라우저에만 저장됩니다.
3. [설정] 에서 AI 도구 연동 명령을 복사해 한 번 실행하면, 이후 "연구노트에 기록해" 라고 말하면 됩니다.

## 공지

관리자·리드가 올린 안내(발표 준비 요령, 제출 형식, 일정 등)는 **홈 상단 카드**와 **팀 페이지 [공지] 탭**에 보입니다. 고정된 공지는 팀 페이지 상단 띠에도 제목이 뜹니다. AI 도구에게 "공지 읽어줘" 라고 하면 같은 내용을 읽고(`list_notices`), 발표 자료·기록을 도울 때 그 요구사항을 따릅니다.

## 팀 로비

여러 팀에 동시에 속할 수 있습니다. [팀 로비] 에서 전체 팀의 설명·구성원·최근 활동을 보고 **가입**(정책에 따라 즉시 또는 리드 승인)하세요. 가입하면 상단 메뉴에 팀이 생기고, 팀 페이지의 보드·구성원·활동에서 팀원들과 서로의 진행을 봅니다. 탈퇴는 로비에서(진행 중인 내 프로젝트가 있으면 먼저 정리).

## 프로젝트 = 논문 하나

홈이나 팀 페이지에서 **+ 새 프로젝트**. 제목(가제)·연구 질문 요약·목표 학회·마감·태그. 시작 단계는 보통 "기획".

## 기록하는 법 (하루 5분)

홈의 **오늘의 기록** 또는 프로젝트의 **+ 기록 추가**:

- **연구일**: 실제로 한 날짜 (어제 한 일을 오늘 쓰면 어제)
- **단계**: 그 작업이 논문의 어느 부분인지 (기획/리서치/관련기법/실험결과/논문작성/검토)
- **제목**: 결과가 드러나게 — "ResNet-50 baseline, CIFAR-10 acc 91.2%" (좋음) / "실험" (나쁨)
- **내용** (마크다운):

```markdown
## 한 일
- 데이터셋·모델·설정·실행 명령

## 결과
| 모델 | Acc | 비고 |
|---|---|---|
| A | 0.91 | seed 0 |

## 다음 할 일
- [ ] 시드 5개 반복

## 메모
- 막힌 점, 리드에게 묻고 싶은 것
```

실패한 실험도 기록하세요. 원인 가설과 함께 남긴 negative result 는 나중에 논문의 ablation 이 됩니다.

## 단계별 정리 = 논문의 뼈대

프로젝트 → **단계별 정리** 탭. 각 단계의 **누적 결론**을 씁니다. 날짜별 기록이 "일기" 라면 단계별 정리는 "요약본". 예:

- 기획: 연구 질문 · 가설 H1/H2 · 기여점 3개
- 리서치: 핵심 선행연구 표 · 우리 차별점
- 관련기법: 모델 · 실험 설계 · 비교군
- 실험결과: 현재까지 표 · 남은 실험
- 논문작성: 절별 체크리스트
- 검토·투고: 리뷰 코멘트 대응표

단계는 한 흐름으로 진행됩니다. 현재 단계가 끝나면 상단 또는 단계 카드의 **[다음 단계로 →]** 버튼을 누르세요. 앞 단계는 자동으로 완료, 뒤 단계는 예정으로 표시됩니다. 마지막(검토·투고)에서 누르면 **논문 완료**. 리뷰어 요청 등으로 실험을 다시 해야 하면 그 단계 카드의 **[이 단계로 되돌리기]** (정리 내용은 유지). 보고서는 이 순서대로 생성됩니다.

## 검토 받기

기록 저장 시 **리드에게 검토 요청** 체크, 또는 기록 카드의 **검토 요청** 버튼. 리드가 코멘트·승인·수정요청을 남기면 기록 테두리 색이 바뀝니다. 코멘트에 답글을 달고 수정 후 다시 요청하세요.

같은 팀 기록에는 누구나 코멘트할 수 있습니다. 팀 페이지 → 보드에서 동료 프로젝트를 열어 보세요.

## 캡스톤(팀 프로젝트)이라면

- 팀 대표가 프로젝트를 만들고 [팀] 탭에서 팀원을 **협업자**로 추가하면 모두가 기록·단계 정리를 쓸 수 있습니다.
- 단계는 주제·문제 발견 → 시장·사업모델 → MVP 빌드·배포 → 피드백·개선 → 사업성·최종보고 → 최종 발표. 각 단계 카드에 마일스톤(1차·2차·최종 보고서, 데모·최종 발표)이 표시됩니다.
- 루프(가설→빌드→배포→피드백→학습)를 돌 때마다 날짜별 기록을 남기고 제목에 루프 번호를 붙이세요. 매주 진행 보고가 곧 이 기록입니다.

## 평가·피드백

[평가·피드백] 탭에 평가자(리드·조교·심사위원)들이 마일스톤마다 남긴 루브릭 점수와 피드백이 모입니다. 각 평가에 **답변**(무엇을 어떻게 반영할지)을 달아 두면 다음 보고서의 "평가의견 답변"으로 보고서에 자동 포함됩니다. 평가자가 여러 명이면 단계별 평균이 표시됩니다.

## 할 일

프로젝트 → **할 일** 탭. 기록의 "다음 할 일" 을 실제 항목으로 옮기고, 끝나면 체크. 기한이 지나면 붉게 표시.

## 보고서

프로젝트 → **보고서** → 기간 선택 → **HTML 보고서 열기** → 상단 [인쇄 / PDF 저장]. 주간 미팅 자료가 됩니다. Markdown 다운로드는 Overleaf·노션에 붙일 때.

## AI 도구와 함께

Claude Code 에서 연구 코드를 돌리다가:

- "지금 결과 연구노트에 기록해줘" → AI 가 실험 설정·수치·다음 할 일을 정리해 기록 (source 가 "AI 기록" 으로 표시)
- "실험 단계 정리 갱신해" → 단계별 정리에 누적
- "이번 주 주간 보고 초안 만들어" → 보고서 기반 초안
- "팀원들 뭐 하고 있어?" → 팀 피드

AI 는 여러분이 실제로 한 일만 기록하도록 지시받았지만, 저장 전에 내용을 확인하는 습관을 권합니다. 기록은 언제든 수정할 수 있습니다.

## 자주 묻는 것

- **"유효하지 않은 토큰" / "토큰 형식이 아닙니다" 라고 나와요** → 로그인 창에는 **rn_ 로 시작하는 43자 토큰**을 넣어야 합니다. 신청 직후 받은 **수령 코드(clm_)** 는 토큰이 아닙니다: `/#/claim/<수령 코드>` 에서 [토큰 받기]를 눌러 토큰을 먼저 받으세요 (승인 후 1회). 붙여넣을 때 앞뒤가 잘리거나 따옴표·공백이 섞여도 자동으로 정리됩니다
- **수령 코드를 잃어버렸어요** → 관리자에게 "수령 코드 재발급"을 요청하세요 (새 링크에서 다시 [토큰 받기]). 같은 이메일로 다시 신청하면 중복이라 막힙니다
- **토큰을 잃어버렸어요 / 새 기기에서 쓰고 싶어요** → 로그인 페이지의 **토큰 재발급**(`/#/reissue`)에서 등록한 이름·이메일을 입력하면 일치할 때 새 토큰이 **바로** 발급됩니다. 기본으로 기존 토큰은 회수되니(분실·유출 대비) 다른 기기에서 계속 쓰려면 "기존 토큰 회수"를 끄세요. 5회 틀리면 10분 잠금, 시간당 3회까지
- **다른 팀 프로젝트가 안 보여요** → 같은 카테고리 구성원만 볼 수 있습니다. 관리자에게 소속 추가 요청
- **기록을 잘못된 프로젝트에 남겼어요** → 삭제 후 다시 작성 (프로젝트 간 이동은 미지원)
- **그림·파일 첨부** → 마크다운 링크로 (Drive/Overleaf/Git 링크). 업로드는 로드맵
- **가입 없이 보기만 하고 싶어요 (심사위원·참관자)** → 팀이 공개로 설정돼 있으면 `/#/view` 에서 핀만 넣으면 24시간 읽기 전용으로 볼 수 있습니다. 핀은 연구책임자·리드에게. 기록·코멘트는 할 수 없습니다
